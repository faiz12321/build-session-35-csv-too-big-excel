Split a large CSV by records, without replacing existing files

Short answer

An Excel worksheet has 1,048,576 rows, including the header. A CSV record can span several physical lines, so counting lines is not enough. This Python tool counts parsed UTF-8 comma-separated records and can split them into a new folder with a header in every part. It checks ordered parsed values against a source digest, not byte-for-byte identity or full Excel compatibility.

Common mistakes

  1. Counting physical lines. Quoted fields can contain newlines. Parse records instead.
  2. Forgetting the header row. With one header, the maximum data-record count is 1,048,575, not 1,048,576.
  3. Calling a part compatible with Excel based on rows alone. Columns, cell limits, formulas, conversions and import settings are not checked.
  4. Reusing an output folder. The splitter refuses existing paths. Keep originals and inspect any incomplete output after an error.

Frequently asked questions

What limit is checked?

Only worksheet row count: 1,048,576 total rows, leaving 1,048,575 data records when one header row is used. Microsoft also documents column and cell limits, which this tool does not check.

Does it preserve the original bytes?

No. It writes parsed string fields with csv.writer, UTF-8 and CRLF record endings. Quoting, BOM and line endings can change. It verifies ordered parsed field values with a SHA-256 digest against the first source scan.

What about quoted multiline fields?

Python csv.reader parses them as one record when files are opened with newline="". The splitter writes whole records. Tests cover embedded LF, bare CR, commas and quotes.

What happens if output already exists?

It refuses the path without resetting it. Each new part is also exclusively created. Other errors can leave a new folder with partial output. Do not use unverified parts or delete old data to force a retry.

Does a verified split mean Excel is safe?

No. It checks counts, headers and ordered parsed fields, not formulas, number conversion, column/cell limits, content accuracy or import settings. Keep the original and inspect an import before relying on it.
